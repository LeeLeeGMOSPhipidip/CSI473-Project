# Remmogo Consistency Matrix

## Conventions

This matrix is based on the approved proposal, functional requirements, acceptance criteria, business rules, CRC cards, domain model, quality scenarios, use-case model, sequence diagram, activity diagram, and Rental state machine.

The Rental lifecycle states used in this matrix are: `PendingTransaction`, `Reserved`, `WaitingForCustomerConfirmation`, `WaitingForOwnerConfirmation`, `ActiveRental`, `Overdue`, `Completed`, and `Cancelled`.

## Matrix

| Use-case step | Proposed sequence message | CRC/domain responsibility | State or lifecycle effect | Requirement / rule / acceptance evidence |
|---|---|---|---|---|
| **Sign in - 1.** Student enters account credentials. | `signIn(ubEmail, password)` | `Account` authenticates the Student and protects account access. | Account must be active; no Rental state change. | FR-02; business rule: only registered users with valid UB accounts may access protected functions. |
| **Search for items - 1.** Customer enters an item name or category. | `searchItems(query, category)` | `ItemListing` provides searchable details; `Category` supports classification and filtering. | No Rental state change. | FR-05, FR-06; Quality Scenario 2. |
| **View available items - 1.** System returns matching available listings. | `findAvailableListings(criteria)` | `ItemListing` protects its availability status and quantity. | Guard: `[availableQuantity > 0 AND status = AVAILABLE]`; no Rental state change. | FR-07, FR-11; business rule: unavailable listings must not appear in the storefront. |
| **View item details - 1.** Customer selects a listing and views its details. | `getItemDetails(listingId)` | `ItemListing` supplies the item name, category, condition, description, rental price, and available quantity. | No Rental state change. | FR-04; Successful Rental Request acceptance criterion. |
| **Send rental request - 1.** Customer enters the rental period and quantity and submits the request. | `sendRentalRequest(listingId, rentalPeriod, quantity)` | `Rental` validates the request with `Account` and `ItemListing`; `ItemListing` verifies that the requested quantity is available. | Guard: `[signed in AND valid UB account AND quantity available]`; Rental enters `PendingTransaction`. | Use case: Send Rental Request; Successful Rental Request acceptance criterion; approved proposal workflow. |
| **Send rental request - 2.** System creates the pending Rental record. | `createRental(customer, owner, listing, period, quantity)` | `Rental` records the participants, listing, rental period, quantity, agreed price, and current status. | `Rental: initial -> PendingTransaction`. | Successful Rental Request acceptance criterion; Quality Scenario 3. |
| **Send rental request - 3.** System notifies the Owner of the request. | `notifyOwner(rentalId)` | `Rental` coordinates the notification to the correct Owner. | Rental remains `PendingTransaction`. | Successful Rental Request acceptance criterion. |
| **Send rental request - A1.** Requested quantity becomes unavailable or the request cannot be fulfilled. | `cancelRental(reason)` | `Rental` records the failed request; `ItemListing` prevents its available quantity from dropping below zero. | `Rental: PendingTransaction -> Cancelled`. | Prevent Duplicate Booking acceptance criterion; FR-07; business rule on item availability. |
| **View rental request - 1.** Owner views the pending request. | `viewRentalRequest(rentalId)` | `Rental` supplies the Customer, listing, rental period, requested quantity, agreed price, and status. | Rental remains `PendingTransaction`. | Use case: View Rental Request; approved proposal workflow. |
| **View rental request - 2.** Owner accepts the request while the requested quantity is available. | `acceptRentalRequest(rentalId)`; `reserveQuantity(quantity)` | `Rental` records acceptance; `ItemListing` reserves the requested quantity to prevent double booking. | Guard: `[quantity available]`; `Rental: PendingTransaction -> Reserved`; the system then notifies the Customer and enters `WaitingForCustomerConfirmation`. | Proposal Objective 2; Prevent Duplicate Booking acceptance criterion; business rule on reserving available items. |
| **View rental request - A1.** Owner rejects the request or a participant cancels before activation. | `cancelRental(reason)`; `releaseQuantity(quantity)` | `Rental` records cancellation; `ItemListing` releases any reserved quantity. | `Rental: PendingTransaction/Reserved -> Cancelled`. | Proposal Objectives 2 and 3; cancellation rule. |
| **Chat with user or admin - 1.** Customer and Owner communicate about rental arrangements. | `sendMessage(rentalId, content)` | `Conversation` contains each `Message`; only authorised participants may send and view messages. | No Rental state change. | FR-12; CRC communication responsibility; Quality Scenario 4. |
| **Confirm payment made - 1.** Customer confirms that payment was made outside Remmogo. | `confirmPaymentMade(rentalId)` | `PaymentConfirmation` records the confirming Customer and confirmation time; `Rental` prevents duplicate confirmation. | `Rental: WaitingForCustomerConfirmation -> WaitingForOwnerConfirmation`. | FR-08; Payment Confirmation acceptance criterion; explicit out-of-scope rule for payment processing. |
| **Confirm payment received - 1.** Owner confirms receiving the payment. | `confirmPaymentReceived(rentalId)` | A second `PaymentConfirmation` is recorded; `Rental` verifies that the Customer and Owner have both confirmed. | Guard: `[customerConfirmed AND ownerConfirmed]`; Rental remains `WaitingForOwnerConfirmation` until handover is confirmed. | FR-08; Payment Confirmation acceptance criterion; business rule requiring confirmation by both parties. |
| **Payment confirmation - A1.** The required confirmation is not received within 48 hours. | `checkPaymentConfirmationDeadline()`; `cancelRental(reason)`; `releaseQuantity(quantity)`; `notifyParticipants()` | `Rental` enforces the confirmation deadline and coordinates cancellation and notifications; `ItemListing` releases the reservation. | `Rental: WaitingForCustomerConfirmation/WaitingForOwnerConfirmation -> Cancelled`; Rental must not become `ActiveRental`. | Handling Payment Not Confirmed acceptance criterion; payment confirmation deadline rule. |
| **Confirm item handover - 1.** Owner confirms that the item has been handed over after both payment confirmations are present. | `confirmHandover(rentalId)` | `Rental` verifies both payment confirmations, records the handover and due date, and activates the rental; `ItemListing` retains the reduced available quantity. | Guard: `[customerConfirmed AND ownerConfirmed]`; `Rental: WaitingForOwnerConfirmation -> ActiveRental`. | Use case: Confirm Item Handover; approved proposal core workflow. |
| **Overdue check - A1.** The due date passes without a confirmed return. | `checkDueDate()`; `markOverdue()`; `notifyParticipants()` | `Rental` enforces the due date, marks the rental overdue, and coordinates notifications. | `Rental: ActiveRental -> Overdue`. | Return and Overdue Management acceptance criterion; proposal exception flow; Quality Scenario 6. |
| **Confirm item return - 1.** Customer records return confirmation and the item's condition. | `confirmReturn(rentalId, condition)` | `ReturnConfirmation` records the Customer, time, and condition; `Rental` prevents duplicate confirmation. | Rental remains `ActiveRental` or `Overdue` until both parties confirm the return. | FR-09; approved proposal core workflow. |
| **Confirm item return - 2.** Owner confirms receiving the returned item. | `confirmReturn(rentalId, condition)` | A second `ReturnConfirmation` is recorded; `Rental` verifies both confirmations and closes the transaction. | Guard: `[customerConfirmed AND ownerConfirmed]`; `Rental: ActiveRental/Overdue -> Completed`. | FR-09; Return and Overdue Management acceptance criterion; business rule on completed rentals. |
| **Confirm item return - 3.** System restores the returned quantity. | `increaseAvailableQuantity(quantity)` | `ItemListing` updates the available quantity without allowing it to exceed the total quantity. | Listing becomes visible whenever `availableQuantity > 0`; Rental remains `Completed`. | FR-07, FR-11; business rule on listing availability. |
| **Rate user - 1.** Either Rental participant rates the other participant. | `submitRating(rentalId, score, comment)` | `Rating` stores the feedback and associates it with the completed Rental and its two participating Students. | Guard: `[Rental = Completed]`; no Rental state change. | FR-10; business rule: only participants in a completed rental may rate each other. |
| **Manage disputes - 1.** Student reports a late, damaged, cancelled, or disputed rental. | `submitReport(rentalId, type, description)` | `Report` records the issue; `Administrator` reviews it and records its resolution. | `Report: OPEN -> UNDER_REVIEW -> RESOLVED/DISMISSED`; Rental state normally remains unchanged. | FR-13; Proposal Objective 3; business rule on administrative reports. |
